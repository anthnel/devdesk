  ## Hypothèses (choix prudents, à valider en revue)
  
  - **Contrôle de route préalable.** Avant d'ouvrir les handles, une socket UDP est connectée (`udp4` ou `udp6`, port 33435, **aucun paquet envoyé**) :
    - un échec de route arrive alors comme `WSAENETUNREACH`, traduit en `ErrNoRoute` avant toute sonde, comme sous Linux ;
    - `LocalAddr` fournit la `SourceAddress` qu'exige `Icmp6SendEcho2`.
  - **RTT** : mesuré à l'horloge comme sous Linux (`reply.RTT` = 0). On n'utilise pas `RoundTripTime`, dont la granularité est la milliseconde.
  - **`IP_SUCCESS`** = `HopTarget`, même si l'adresse diffère de la cible (une réponse d'écho ne vient que de la pile de la destination).
  - **`IP_DEST_*_UNREACHABLE`** = `HopUnreachable`, même venant de la cible.
  - **IPv6 lien-local (fe80::/10)** : refusé avec `ErrNotUnicast` (il faudrait une zone).
  - **`Hop.Err` sur Windows** porte un code typé (`EchoStatusError{Status}`, `Error()` = `"ICMP status 11050"`). Jamais de texte `FormatMessage`.

  ### Étape 5 : `echoConn` / `echoProber` sur une API abstraite (M, tous OS, dépend de l'étape 4)
  
  - **Fichier** `echo_conn.go` (sans tag) :
    ```go
    type echoAPI interface {
        create(v6 bool) (uintptr, error)
        // echo blocks until a reply, the timeout, or a failure; it returns errSilent on timeout.
        echo(h uintptr, src, dst netip.Addr, ttl int, timeout time.Duration) (reply, error)
        closeHandle(h uintptr) error
    }
    type echoProber struct {
        api       echoAPI
        preflight func(ctx context.Context, dst netip.Addr) (src netip.Addr, err error) // UDP connect, no packet
        src       netip.Addr // set by the first open; openAll calls open sequentially
    }
    func (p *echoProber) open(ctx context.Context, dst netip.Addr, ttl int) (probeConn, error)
    ```
  - **Comportement**
    - `send()` note `sentAt`.
    - `await(ctx, until)` lance `api.echo` dans une goroutine (canal tamponné de taille 1), avec timeout `until − now`, au minimum 1 ms. Il fait un `select` entre le résultat et `ctx.Done()`. Si l'appel renvoie `errSilent` et que `ctx` expire au plus tard à `until` : `<-ctx.Done()`, puis on renvoie `ctx.Err()`, comme sous Linux.
    - `close()` est idempotent. Si un appel est en vol, la goroutine ferme le handle à son retour, sinon on le ferme tout de suite.
    - Correspondance des erreurs :
      - un échec du préalable qui vérifie `IsNoRoute` → `connectError`, donc `ErrNoRoute` ;
      - `create` échoue avec `ERROR_NOT_SUPPORTED` ou `ERROR_ACCESS_DENIED` → `fmt.Errorf("%w: %w", ErrUnsupported, err)`. Ces errnos sont injectés par la plateforme : le fichier neutre ne les nomme pas.
  - **Tests** (`echo_conn_test.go`, API factice dont `echo` bloque sur un canal) :
    - la réponse donne le bon `Hop` ;
    - annulation pendant un `echo` bloqué → `await` renvoie `context.Canceled` en moins de 50 ms ; `closeHandle` n'est pas appelé avant la libération du factice, puis une seule fois ;
    - `close` sans `await` → fermeture immédiate, une seule fois ;
    - timeout transmis ≈ `until − now` ;
    - TTL transmis ;
    - préalable sans route → `errors.Is(err, ErrNoRoute)` et aucun `create` ;
    - `run()` avec 30 TTL → 30 `create` et 30 `closeHandle` après libération ; aucune goroutine restante (compteur dans le factice) ;
    - `-race` sous WSL2.
  - **Commande** : `go test ./internal/nettrace -run "EchoConn|EchoProber" -v` ; sous WSL2 : `mise run test-race`.

  ## Risques
  
  1. **Disposition mémoire non vérifiée.** `ICMPV6_ECHO_REPLY`, compacté ou non, et `IP_OPTION_INFORMATION` en 64 bits sont lus d'après `ipexport.h`, sans vérification ici. Le test loopback et le test de disposition de l'étape 6 doivent passer avant de brancher l'UI. windows/arm64 est publié mais ne sera pas mesuré.
  2. **Threads et goroutines.** Un thread OS bloqué par sonde : jusqu'à 30, environ 60 lors d'un « Trace again » pendant une trace. Après une annulation, les goroutines internes survivent au plus ProbeTimeout (3 s), handle fermé à leur fin. Le contrat `onHop` (jamais après le retour) est préservé, et un test vérifie qu'aucune goroutine ne reste.
  3. **Écart de méthode.** Les résultats Windows et WSL2 diffèrent pour une même cible (écho filtré, limitation de débit). Il faut le dire dans D154 et dans `network.md`.
  4. **`DEST_HOST_UNREACHABLE` local.** Sur un échec ARP du lien local, Windows peut renvoyer ce statut avec la propre adresse de la machine : on obtient un saut `unreachable` à cette adresse. Accepté, à noter.
  5. **CI aveugle sur Windows** sans Q2 : le moteur Windows n'est ni vérifié par vet, ni linté, ni testé en CI.
  6. **Collision de numéro D** avec une branche concurrente.
