    - **Key names:** `ctrl+`, `alt+`, `shift+` and `cmd+` chords; `esc` and `ctrl` on their own; a letter between angle brackets (`<Y>`, `<Enter>`); `F1` to `F12`; "enter key" and similar; the words press, hit, keystroke, keybinding and shortcut.
    - **Format:** an empty step, blanks around a step, a line break inside one, a step that does not start with a capital letter or end with a period, and a duplicate step.

  - **Repro:** the AST scan fails if a `Finding.Repro` is set from anything but `localRepro` or a wrapper. It finds wrappers itself: a function whose every return is a producer call, which is how it recognises `renderRepro`.
  - **Steps:** I added the same rule for `Steps`, which must come from a `*Steps` function. Without it, a literal Steps set in a parser would have escaped the content guard.
  - **Site forms covered:** `Repro: x`, `f.Repro = x`, `f.Repro += ...`, and the tuple form `f.Repro, f.RanFrom = a, b`. It also flags a positional `Finding` literal.
  - **What counts as a clean value:** a producer call, a name that only a producer assigned in the function, or a parameter that every caller in the package feeds with a clean value. `""` and `nil` are allowed.
  - **Real code:** it examines 3 Repro sites and at least 5 Steps sites, with floors so a rename cannot turn it into a pass on nothing. It also asserts that `localRepro` exists and that `renderRepro` is recognised as a wrapper.

  - **Limits, also written in the doc:**
    - It works on names, not types, so any struct with a `Repro` or `Steps` field is held to the rule.
    - It does not see aliases, function or method values, a pointer to the field, reflection, or a `Finding` built by another package.
    - It ignores control flow inside a function: a name also assigned from something else is refused, whatever the order.
    - Functions are keyed by name, so two methods with the same name share one entry.
