It performs a real, synchronous round trip through `github.com/zalando/go-keyring` (`v0.2.8`, confirmed in `go.mod:21`) — on Linux this is a genuine Secret Service D-Bus call reading a never-written probe account (`keyringProbeAccount`, line 21). ## 2. `internal/engine` and `internal/docker` — daemon reachability

**`engine.Resolve(preference string) (Shape, error)`** — `internal/engine/engine.go:193-219`. It **only** does `exec.LookPath(name)` (binary-on-PATH check). **`internal/docker`** — no dedicated "is the engine reachable" function either, but three existing calls already perform real daemon round-trips and expose an `Available bool`:
- `requireEngine()` — `internal/docker/exec.go:98-103` — only checks `runner.LookPath()` (binary presence), **not** the daemon.
- `docker.FetchCapacity() (Capacity, error)` — `internal/docker/containers.go:185-207` — calls `requireEngine()` then runs `&lt;engine&gt; info --format {{.NCPU}}\t{{.MemTotal}}`. - `docker.FetchOCIStats() OCIStats` — `internal/docker/system.go:39-93` — runs `&lt;engine&gt; system df`; sets `stats.Available = true` only on success (line 51). Requires the daemon.
- `docker.FetchAggregateMetrics() Aggregate` — `internal/docker/containers.go:219-238` — combines `GetContainerMetrics()` (`docker stats`) and `FetchCapacity()` (`docker info`); `Available` is true only if both succeed (`aggregate()`, line 242-253).

None of these is named or shaped as a plain "yes/no is this engine usable right now" check — they're all data-fetchers whose success is repurposed as an availability flag, and all of them read the package-global `engine.Current()` rather than taking a `Shape` parameter, so a wizard wanting to test a *candidate* engine (before committing it) would have to `engine.SetCurrent(shape)` first or shell out directly itself.
