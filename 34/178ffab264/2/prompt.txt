  **Summary of the design**
  - Each file has a position stored as a value (`fileCursor`): `offset` (just past the last complete line), `size` seen, `skipFrom` (an over-long line still being written), the file's identity (`os.SameFile`), and its mtime.
  - An incomplete last line is **read again** from `offset` on the next pass, not kept in memory (D1). Over-long lines still being written are resumed in skip mode (D2). Both are counted exactly once.
  - A file whose size has not changed is **never opened**, only `Lstat`'d. This is what criterion 1 can test here: 0 opens on a session where nothing was written.
  - The merge is ordered by line position (parent, then sub-agents by ID, then offset), not by arrival time (D3). As a result, applying deltas one after another gives exactly what `ParseSession` gives on the final files. That equivalence is the main test oracle: fixtures appended chunk by chunk, seeded random sessions, a concurrent writer under `-race`, and a fuzz test.
  - Anything that is not an append triggers a **full re-read of the whole session** (D4): truncation, rotation, deleted file, link swapped in, or the byte before `offset` not being `\n`.
  - `ParseSession` is re-routed through the same path (D5): one computation, and the existing tests guard against regressions.
  - Read errors, open failures and `TruncatedFiles` describe the current state of a file, not past events (D6). Meta files are re-read only when their `Lstat` result changes (D7).
  - `Aggregate` is owned by `Update` only. `Cursor` is a deep copy, and `Apply` refuses a delta not read from the current cursor (`ErrStaleDelta`, D8/D9).
  
  **Proposed public API (frozen for S-05b)**: `Cursor` (+ `Rewound`, `String`/`GoString` redacted), `Delta` (`Full`, `Empty`, redacted), `ReadDelta(c Cursor) (Delta, error)`, `NewAggregate(parent) *Aggregate`, `(*Aggregate).Cursor/Apply/Usage/Activity`, `Activity{LastChange, Unfinished}` + `Settled(now, quiet)`, `ErrStaleDelta`.
